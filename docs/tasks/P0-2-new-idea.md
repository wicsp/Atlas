# P0-2 `lumio new idea`

- 负责：后端（Codex）　Review：Claude
- 相关 ADR：0008、0009
- 涉及：`packages/core`、`apps/cli`
- 依赖：P0-1（复用 vault 定位、frontmatter 写入、ID 生成、补全器、安全写文件）

## 目标
用一条命令创建一篇想法笔记，元数据与 `lumio sync` 补全的结果**完全一致**。

## 用法
```
lumio new idea <标题> [--vault <路径>]
```
示例：`lumio new idea "协议渲染和来源标记的关系"`

## 范围
1. 在 `packages/core` 中新增"创建"流程，按 ADR 0009 的流水线组织：
   输入 → 解析器（idea：只取标题）→ **P0-1 的补全器** → schema 校验 → 写文件。
   **不得为 idea 另写一套元数据生成逻辑**；新文件的元数据必须来自同一个补全器
   （此时 birthtime 与 mtime 都取当前时间）。
2. 文件名：`ideas/<标题>.md`。
   - 标题中不能用于文件名的字符替换为空格：`\ / : * ? " < > | # ^ [ ]`，然后合并连续空格、去掉首尾空格。
   - 中文和其他 Unicode 字符原样保留。
   - frontmatter 中的 `title` 保留原始标题（替换前）。
3. 文件内容：frontmatter，加一个空行，正文为空。
4. 同名文件已存在时：**报错退出，不覆盖**，提示已存在的路径。
5. 成功时输出新文件的相对路径，退出码 0。
6. 标题为空或只有空白：报错退出。

## 不做
- 不打开编辑器，不支持从标准输入读正文（以后再说）。
- 不创建 task、project、experiment。

## 验收标准
1. `bun run check` 通过。
2. 测试：创建后的文件能通过 `@lumio/schema` 的 `Idea` 校验。
3. 测试：**对新创建的文件运行 `lumio sync`，结果为"补全 0 个"**，以此证明两条路径的元数据一致。
4. 测试：文件名非法字符替换规则；中文标题；同名文件不覆盖；空标题报错。
